# brk-public-skills

Brooker 用于公开分享的 Agent Skills。每个目录是一项独立 Skill，包含可阅读、可修改的 `SKILL.md`。

这里分享通用方法和工作流程，不包含作者的个人上下文库、原始聊天、私人项目资料或账号凭证。

## Skills

| Skill | 用途 |
|---|---|
| [personal-context-library](personal-context-library/SKILL.md) | 根据可访问的聊天、GitHub 项目、本地资料与作品，建立可供不同 Agent 接手的个人上下文库；核对真实进度、维护近期计划，完成后可选择每周总结。 |

## 安装

通过 [Skills CLI](https://github.com/vercel-labs/skills) 安装指定 Skill：

```bash
npx skills add Brooker-Fang/brk-public-skills --skill personal-context-library
```

按提示选择目标 Agent。需要安装到用户级目录时，可添加 `-g`。

只查看仓库中有哪些 Skill，不安装：

```bash
npx skills add Brooker-Fang/brk-public-skills --list
```

也可以复制某个 Skill 的整个目录，放入所用 Agent 支持的 Skills 目录。若当前环境不支持 Skills，可将 `SKILL.md` 正文作为任务说明交给助理；可用工具和资料访问范围仍由当前环境决定。

## 使用个人上下文库 Skill

可以这样提出请求：

> 请使用 personal-context-library，整理你当前能读取的聊天、我的 GitHub 项目和我提供的本地资料，建立个人上下文库。先确认知识库放在哪里；整理、核对并交付后，再问我是否需要每周定时总结。

工作流程：

1. **先确定保存位置**：飞书知识库、本地文件夹、GitHub 私有仓库或其他可用位置；已有配置直接复用。
2. **收集与核对**：说明实际覆盖范围，核对消息、代码、任务表和产物；区分用户决定、助手建议、已完成、推进中和未来候选。
3. **分层整理并交付**：快速入口、项目详细档案、近期计划、成果、Skills、账号作品及来源相互关联；保存后回读验证。
4. **完成后选择每周维护**：询问是否需要定时总结。选择需要时，再确认时间、时区、保存位置和通知方式；使用环境已有的调度工具，优先复用已有任务。

后续更新可以说：

> 根据本次对话更新个人上下文库，将完成项移出近期待办，保留来源和日期，把我的决定与你的建议分开记录。

## 能力与资料范围

- Skill 提供工作方法；能否读取其他聊天、私有仓库或云文档，取决于助理当前的连接、授权和工具。
- 飞书可用时优先采用官方 CLI；没有相应工具时，可先整理本地 Markdown，再说明尚未同步的部分。
- 每周总结依赖当前环境的调度能力。没有该能力时只交付手动总结说明，不宣称已设置后台任务。
- 本公开仓库与个人知识库的主库、备份和公开演示版分别维护。资料整理不自动触发项目开发、内容发布或其他历史任务。

## 添加新的 Skill

为新 Skill 创建一个独立目录，至少包含带有 `name`、`description` 的 `SKILL.md`，并更新上面的目录表。只收录适合公开复用的说明与必要资源。
