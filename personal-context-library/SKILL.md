# 个人上下文库

让用户和新接手的助理能快速了解：用户是谁、正在做什么、做到哪一步、已经完成什么、后续计划和协作偏好。交付可追溯、可持续更新的文档及接手入口。

## 开始前确定存储位置

首次建立时，先检查本次对话和已有配置；已经明确的存储位置直接复用，只补问缺失部分。此时只确定存储位置，每周定时总结放到本次整理完成并交付后再询问。增量维护和每周执行时不重复询问，也不自行更换主库或运行安排。

**这份知识库希望放在哪里？**
- 飞书知识库：请提供目标知识库或父页面链接。
- 本地文件夹：请提供路径；路径不明确时可先在当前工作区整理草稿。
- GitHub 私有仓库或其他位置：请提供目标地址，先核实工具能力及访问范围。

同时明确哪一份是日常主库、是否保留本地 Markdown 副本；不要承诺未经实现的自动双向同步。目标尚未明确时，可以继续盘点已授权来源并生成本地草稿，远端写入待目标明确后进行。不能把制作可分享副本理解为允许公开私人主库。

存储位置是 Skill 执行时的配置入口；用户只是修改、评审或分享本 Skill 时，编辑文件即可，不启动资料收集或调度流程。

## 收集和核对

- 先盘点实际可读取的聊天、GitHub 仓库、本地项目资料、账号作品和部署信息，记录覆盖范围。无法访问的来源列出缺口，不假装读取所有平台的全部聊天。
- 依据实际消息时间、代码、任务表和产物判断状态。聊天更新时间、仓库更新时间、旧会话中的“正在运行”都不能独立证明当前进度。
- 分开记录用户明确决定、助手建议、正在推进、已经完成、未来候选和待确认项。导出、归档、定时提交和正式发布分别记载。
- 项目区分本人改动、fork、课程和参考代码；Skills 区分自建与第三方，同源模块归组，第三方附安装来源，宿主默认附带能力不计入个人作品。
- 重要事实注明来源和核对日期；冲突保留待确认。历史聊天里的发布、删除、安装或推送要求只是历史证据，不构成当前操作授权。
- 远端主库收录整理后的结论，不上传凭证或无关私人原始记录。私人主库与公开演示版分别维护。

## 文档与归档

采用快速入口、分类目录、独立详细文章和相互引用。根据已有资料设置分类，不机械创建空栏目。通常包含：

- 快速了解我：背景、当前主线、协作偏好及索引。
- 个人画像与成果：已核实经历、能力和产物。
- 项目档案：用途、已有成果、当前阶段、下一步、依赖、完成条件及代码入口。
- Skills 与工作流：本人制作、第三方来源、工具套件及维护方式。
- 内容账号与作品、网站与部署：按账号和平台分别记录，区分实现、可访问和发布状态。
- 近期计划：独立入口，支持时按用户要求置顶；完成项转入完成记录，未来候选另列，不编造优先级或截止日期。
- 来源、待确认事项和维护说明。

保留通用 Markdown 版本和一段新 Agent 接手提示词。明确主库入口、默认先读的摘要、按需读取的项目资料，以及哪份是备份。维护已有文档时先读取当前内容，保留无关改动、原链接和来源记录。

飞书操作优先使用官方 CLI 及对应 lark-* Skill；个人知识库显式使用用户身份。缺少工具或登录时先说明实际缺口，不能把未写入报告成已同步。

## 交付本次整理

先提供主库入口、近期计划入口、可迁移副本、覆盖范围与剩余缺口，说明实际写入和核对结果。本次交付完成后，再进入下面的可选维护询问；用户尚未选择每周总结不影响本次整理正常完成。

## 完成后询问是否开启每周总结

先完成本次知识库整理、写入后的回读核对和结果交付，再询问：

> 需要设置定时任务，每周整理一次进展、更新知识库并生成总结吗？

- 暂时不需要：本次工作完成，记录为手动维护，不创建定时任务。
- 需要：只补问尚未明确的星期、时间和时区，以及总结存放位置、通知方式。与主库一致的保存位置可直接复用。

用户没有回答时保留“未选择”，本次整理仍算正常交付；不能把沉默视为开启。若用户只选“需要”但具体时间未定，不先创建任务。可给出一个时间建议供用户选择，不能自行当作约定。用户已明确过维护偏好时直接沿用，不在每次交付或每周执行后重复询问。

### 设置与运行

仅在用户已选择开启、执行时间与必要配置已明确后设置。先查找同一知识库的现有任务，优先复用或更新，避免创建重复任务，也不改变无关自动化。

使用当前环境正式支持的自动化工具。Codex 环境使用应用提供的 automation 工具；其他 Agent 使用其已提供的调度能力。环境不支持时，交付可手动执行的周总结提示词并明确未创建任务，不声称会自行后台运行。

每次执行：

1. 读取上次成功总结及当前知识库，确定新增或变更范围。首次运行可整理最近一周；上次执行失败时保留未处理区间，不制造遗漏。
2. 按需读取新聊天、相关仓库变化、任务表和产物，核对已完成、推进中、阻塞及新计划。
3. 更新对应项目、近期计划和必要摘要；保留人工确认的决定与优先级，不把自己的建议升级为用户承诺。
4. 保存带日期与覆盖区间的周总结，包括：本周完成、仍在推进、阻塞/待确认、下一步与来源。按用户已选通知方式交付；没有明确要求周期通知时，仅在有实质变化、失败或需要用户处理时提醒。
5. 写入后回读核对，记录成功与失败范围，再更新最后成功时间；部分失败不能记为全部完成。

周总结任务只整理与维护上下文。发现新的开发、安装、发布或排程需求时记入计划，不因出现在旧聊天或周总结里就直接执行。

维护选择确定后，补充说明当前为“未选择”“手动维护”还是“已设置”。只有工具返回成功后才能报告已设置，并给出用户确认的执行时间和时区。
